## 1. 目标与原则

目标是将个人论文 RAG 应用演进为支持多个用户和工作空间的可信科研工作台：用户能够导入、阅读、比较和管理论文，得到具有原文证据的回答，并在服务重启、模型变更和数据迁移后保持可审计性。

实施原则：

1. **先建立质量基线。** 用人工校准的评测集判断检索、Agent、视觉输入和模型变化的收益。
2. **权限由程序执行。** 模型生成的参数、客户端传入的 ID 和文档内容不能决定访问权限。
3. **证据与推断分开。** 有引用、原文匹配和结论被支持是不同状态。
4. **任务与 API 生命周期解耦。** 重启应支持恢复或清楚标明无法恢复的阶段；避免无审计的重复付费调用。
5. **保留模块化单体。** 先建立服务和存储边界，再按实际负载独立部署 Worker；不以微服务数量作为成熟度指标。
6. **所有数据都有归属和版本。** 权限、解析、Chunk、向量、Prompt、模型、评测和删除策略均可追踪。
7. **受控地增加复杂度。** 多 Agent、GraphRAG、新模型和工作流引擎须证明对目标任务有增益。

## 3. 多用户领域与权限设计

### 3.1 隔离单位

建议以 **Workspace（工作空间）作为租户边界**，以 User 作为登录主体。每名用户可以属于多个工作空间；个人用户拥有个人工作空间，后续团队协作复用相同模型。

第一版共享范围建议限定为工作空间内部。跨工作空间共享、公开链接、匿名访问和外部访客单独设计，默认关闭，避免隐式扩大权限。

建议的核心实体：

| 实体 | 必要关系或字段 | 约束 |
| --- | --- | --- |
| User | 外部身份 subject、显示信息、状态 | 身份绑定稳定 ID，不以可变邮箱作为主键 |
| Workspace | ID、名称、状态、配额策略 | 所有业务资源必须归属工作空间 |
| Membership | workspace_id、user_id、role、status | 成员禁用或移除后立即失去新访问权限 |
| Document | workspace_id、上传者、当前解析版本、删除状态 | 内容哈希是去重依据，不是授权依据 |
| Parse / Chunk | workspace_id、document_id、版本与来源 | 不得关联其他工作空间的文档 |
| Collection | workspace_id、owner_id、visibility | 个人集合与工作空间集合明确区分 |
| PersonalPaperState | workspace_id、user_id、document_id | 收藏、阅读进度默认用户私有 |
| Conversation / Run | workspace_id、owner_id、visibility、parent_run_id | 默认私有；父轮关系必须满足权限与会话约束 |
| Job / Evaluation | workspace_id、actor_id、源资源 ID | Worker 处理前及关键读取时检查授权状态 |
| Review / Annotation | workspace_id、actor_id、版本、审计时间 | 实名主体来自服务端身份，不能自报审核者 |
| Artifact / Cache | workspace_id、资源 ID、版本、保留策略 | 原文、图片、缓存和错误信息同样受隔离约束 |

不要直接沿用当前由全局 PDF 哈希构造的文档 ID 作为多租户业务主键。使用独立文档 ID 与工作空间内哈希去重；即使未来共享底层文件，也必须保留独立授权记录，避免存在性泄露和跨租户删除冲突。

### 3.2 最小权限矩阵

以下是待产品确认的第一版建议。角色之外仍需检查资源可见性和所有者。

| 操作 | Viewer | Member | Admin | Owner |
| --- | --- | --- | --- | --- |
| 阅读获授权论文与共享会话 | 是 | 是 | 是 | 是 |
| 在获授权论文上创建私有问答 | 是，受配额限制 | 是 | 是 | 是 |
| 上传论文、创建集合和笔记 | 否 | 是 | 是 | 是 |
| 分享本人会话到工作空间 | 否 | 是 | 是 | 是 |
| 删除本人私有会话和笔记 | 是 | 是 | 是 | 是 |
| 删除工作空间论文、激活解析版本 | 否 | 否 | 是 | 是 |
| 管理成员和审核权限 | 否 | 否 | 是，不能变更 Owner | 是 |
| 修改预算、供应商配置、删除工作空间 | 否 | 否 | 否 | 是 |

解析 Gold 的标注与复核保持独立人员约束，Admin 身份不能绕过独立复核规则。工作空间管理员不应默认获得所有私有会话正文；若需要支持或合规访问，应另行设计显式授权和审计。

### 3.3 强制执行位置

每次请求建立服务端 `AccessContext`，至少包含 user_id、workspace_id、成员状态和角色。业务服务接收该上下文，底层查询要求显式工作空间条件；后台任务保存主体与资源归属，不保存长期会话凭据。

工具请求的最终范围必须满足：

`有效范围 = 当前主体可访问论文 ∩ 本次用户选择范围 ∩ 工具请求范围`

没有工具范围时沿用本次选择范围；未选择论文时采用明确授权的工作空间范围。空集合必须返回空结果，不能通过 `[] or None` 变成全库检索。越界 ID 应拒绝或按统一契约处理，不能静默扩大范围。

以下入口均需使用同一授权规则：论文列表、元数据、PDF、页图、Block、Chunk、工具调用、检索、引用展开、Run、SSE、导出、评测、审核、缓存与历史恢复。`read_chunk`、`get_paper` 和父轮读取不能因知道 ID 而绕过授权。

PostgreSQL 行级安全可作为纵深防御，但须处理连接池中的租户上下文设置和清理，并测试后台任务路径；不能替代业务层授权。

## 4. 功能演进

### 4.1 证据支持与引用真实性

将当前布尔状态拆分为来源有效性、原文匹配、语义支持和覆盖情况。建议语义状态包括 `supported`、`contradicted`、`insufficient`、`not_checked`，并保存验证器版本、证据集合及理由。

处理流程：

1. 生成结构化 Claim 和其引用 ID，校验格式与 ID 范围。
2. 验证原文区间、Block、页码及解析版本；使用显式字符映射替代按空行推断 Block。
3. 独立验证证据是否支持 Claim，数值断言额外校验单位、指标、实验设置和比较基线。
4. 对证据不足的关键 Claim 在预算内补检索；仍不足则缩小结论、说明缺口或拒答。
5. 展示时区分作者陈述、系统推断、引用定位成功与语义验证成功。

不得将验证模型自报置信度直接解释为正确率。使用人工标注集校准误判，尤其关注“有引用但证据不支持”的 false-pass。

验收：加入有效 ID 但不相关、数字矛盾、单位不一致、引用跨版本等样例；这些样例不能仅因生成 span 就显示“已支持”。

### 4.2 跨论文结构化比较

提供方法、假设、训练数据、计算成本、指标、实验结果和局限性的比较矩阵。每个单元格保存证据、解析版本与缺失状态；不同数据集、划分、指标和实验条件标记不可直接比较。

正则提取元数据保留为候选层。结构化抽取结果必须带来源和审核状态，模型归纳不能覆盖原始事实。支持 Markdown、CSV 和 BibTeX 导出；新增外部文献同步时单独设计账户授权、同步冲突和删除规则。

验收：比较矩阵中的每条事实可回到原文；缺失字段显示未知；不同口径不得直接输出统一排名。

### 4.3 会话与证据记忆

分别保存原始消息、会话摘要、当前独立检索问题、选定论文范围、已验证证据及其版本。追问先解析指代与范围，再检索；历史生成回答只作为会话背景，不作为新的事实来源。

摘要保留引用映射、待解决问题和用户约束，并记录生成版本。恢复历史会话时检查当前权限；文档失权或删除后应隐藏相应内容或显示受控占位，具体保留政策见第 8 节。

验收：覆盖指代、换论文、分支追问、摘要压缩、父轮越权和历史错误传播；不能把其他会话或工作空间的 Run 注入上下文。

### 4.4 论文生命周期与纠错

补充批量导入、重复识别、论文版本关联、元数据编辑、局部纠错、局部重建、删除与导出。人工纠正生成新的派生版本和审计记录，不覆盖供应商原始产物。

重建只更新受影响的 Chunk、向量和关联关系。历史回答固定引用当时版本；重新验证时产生新结果，不原地改写旧回答。

### 4.5 Agent 与多模态预算

保留快速回答、深入回答和图表核验模式。简单问题采用单轮路径；复杂问题根据证据缺口增加调用，是否自动路由以评测结果决定，用户可显式选择。

设置 Run 总耗时、调用次数、输入/输出 Token、图像像素或供应商视觉计费量、费用及重试预算。图片采用相关性筛选、预览和高分辨率区域按需读取，避免仅按图片数量估算成本。

质量路由可以要求视觉证据，但不能越过用户或工作空间的硬预算。无法在预算内获得必要证据时，明确记录未检查范围并返回证据不足。重复工具调用、无新证据和预算耗尽均为可审计停止原因。

## 5. 目标架构与执行模型

### 5.1 组件职责

| 组件 | 职责 | 部署建议 |
| --- | --- | --- |
| Web / 同源入口 | 登录、论文库、会话、证据查看、审核 | 同域反向代理，统一客户端 |
| API | 鉴权、授权、请求校验、任务提交、查询、SSE | 无业务执行状态依赖，支持多副本 |
| 业务模块 | 文档、检索、问答、会话、评测、权限策略 | 先保留模块化单体 |
| Worker | 摄取、问答、重建、评测、删除任务 | 按工作类型独立并发与优先级 |
| PostgreSQL | 业务状态、任务、事件、权限、审计 | 多用户共享元数据事实源 |
| 对象存储 | PDF、原始解析、图片、canonical、导出 | 私有 Bucket，工作空间与版本命名空间 |
| Qdrant 服务 | 文本和视觉向量 | 服务端部署，强制租户/版本过滤 |
| Provider 层 | 连接池、速率、预算、重试、熔断、模型能力 | 进程内共享；跨实例协调配额 |

个人本地模式可继续采用 SQLite、本地文件和嵌入式 Qdrant，通过接口隔离；多人共享模式使用独立配置档，禁止误启嵌入式索引的多进程写入。

### 5.2 持久化任务

API 将请求与任务提交意图持久化，之后由 Worker 领取。使用数据库任务表时通过原子领取和租约避免竞争；引入消息队列时采用事务 Outbox 或等价机制，避免数据库写入成功但消息丢失。

建议统一状态：`queued → running → succeeded / failed / cancelled`，另有 `cancel_requested`、等待重试及死信信息。状态转换带版本号或条件更新，防止完成与取消竞争。

必要机制：

- Worker 租约、心跳、超时回收与最大尝试次数；恢复服务不能把其他活跃 Worker 的任务统一标失败。
- 分阶段检查点：供应商提交、结果下载、规范化、切块、Embedding、索引、激活、检索、生成、验证。
- 幂等键包含工作空间、输入哈希、操作类型和配置版本。
- 对供应商超时但请求可能成功的情况记录不确定状态；能查询原请求则先查询，不能假定重试不收费。
- 取消为协作式传播；已经发送的供应商请求可能继续计费，应记录实际结果和费用。
- 查询与评测任务分池，离线评测不能耗尽在线问答配额；工作空间之间采用公平调度。

采用至少一次执行和幂等步骤，不承诺跨供应商的 exactly-once。初期优先数据库队列；当长流程、定时等待与复杂补偿成为明确需求时，再评估持久化工作流引擎。

### 5.3 事件与 SSE

共享事件表以 `(workspace_id, run_id, seq)` 唯一约束顺序。终态快照与终态事件在数据库事务中提交；SSE 根据持久化序号重放，通知通道只负责唤醒，不充当事实源。

保留 Last-Event-ID、心跳、终态对账与断线重连。多副本 API 均能读取同一日志；限制单用户连接数和慢客户端积压。长连接期间按策略复核权限，成员被移除后不能无限继续接收新事件。

## 6. 存储一致性、索引与迁移

### 6.1 解析版本发布协议

建议候选状态为 `prepared → indexing → ready → active / failed`。先生成不可变产物，完成文本和视觉索引并验证，再在数据库事务内切换当前解析指针。

查询在 Run 创建或检索阶段固定获授权的解析版本集合；跨轮切换版本应显式记录。半完成版本不能进入检索。激活冲突使用条件更新或锁控制。

跨对象存储、数据库和 Qdrant 无统一事务，因此需要补偿和对账：缺失产物、缺失向量、孤立向量、未激活候选、失败上传和过期缓存均有检测与修复流程。垃圾回收遵循保留期，不直接删除历史 Run 依赖的版本。

### 6.2 向量与模型契约

每个索引版本记录 Embedding 模型、可获得的模型修订信息、维度、归一化、图片预处理、Chunker、解析和 Schema 版本。Prompt、生成模型和验证器配置写入 Run 清单。

Qdrant payload 至少包含 workspace_id、document_id、parse_id 和 Chunk ID，为高频过滤字段建立 payload 索引。用户选择范围和权限约束必须在向量检索前应用，不能仅取回 top-k 后再过滤。父子扩展与重排图片读取执行相同规则。

更换模型或处理方式时建立新版本索引，对固定查询集进行影子检索与质量/成本对比，验收后切换并保留回滚窗口。不要在同一向量空间混用不兼容模型。

### 6.3 SQLite 到 PostgreSQL 的迁移步骤

1. 建立版本化迁移工具和 Repository 接口；列出数据库、JSON 文件与事件日志中的全部实体。
2. 创建初始 User、Workspace 与 Membership；旧数据归属必须由部署者明确指定，不自动对所有新用户公开。
3. 建立旧 ID 到新 ID 映射，迁移文档、解析、Chunk、会话、Run、审核、任务与个人状态；同步改写引用关系，保留旧 ID 供追溯。
4. 将本地 Artifact 复制到私有对象存储，以哈希和清单验证完整性，不在复制时删除旧文件。
5. 重建或补写带 workspace_id 的文本、视觉索引，核验数量、抽样内容、版本和权限过滤。
6. 在隔离环境演练迁移、检索、引用跳转和恢复，输出差异报告。
7. 初次切换优先采用维护窗口：暂停新写入与任务领取，完成运行中任务或受控中断，备份后增量迁移，验证再切换。
8. 保留只读旧快照和回滚步骤。新系统开始写入后，回滚必须处理新增数据，不能直接切回旧库丢弃变更。

除非有明确零停机要求，第一版不引入复杂双写；如采用双写，必须明确事实源、顺序、幂等与对账责任。

验收：总量与哈希清单一致，关系无悬挂，历史引用可解析，双工作空间对抗测试通过，恢复演练成功。

## 7. 身份、安全与资源治理

### 7.1 登录与网络边界

优先采用成熟 OIDC 身份提供方或经过维护的认证方案，不自行实现密码系统。Web 与 API 同源部署，使用 Secure、HttpOnly、合适 SameSite 策略的会话 Cookie；写操作同时校验 CSRF/Origin，配置准确 CORS 和可信代理。

Cookie 可覆盖 SSE、PDF 和图片访问。若选择 Bearer 模式，采用支持 Header 的 Fetch 流式客户端；不要将长期 Token 放入 URL。API 客户端使用可撤销、限范围的凭据；共享管理员 Token 不能替代用户身份。

Qdrant、数据库和对象存储不直接暴露给浏览器或公网。对象下载通过授权代理或短时签名链接；签名有效期与撤权要求须一致。

### 7.2 文件与供应商输入

上传限制总字节、页数、文件头与实际可解析性；流式超限立即停止并清理残留文件。对 PDF 渲染、OCR、压缩包下载和解压设置时间、内存、像素、文件数量及展开大小限制。

现有 Zip 路径检查应保留，并补充解压炸弹等资源测试。高风险解析运行在受限容器或进程，避免非必要网络和宿主文件访问；不盲目信任供应商返回的任意 URL。

### 7.3 提示注入与工具边界

PDF、OCR、图注、图片、检索结果和历史回答均属于外部内容。Prompt 明确其数据身份，程序强制工具白名单、参数 Schema、返回大小和资源范围；提示词隔离本身不视为完整防御。

加入要求忽略规则、越界读取、泄露其他论文和伪造引用的测试。未来增加联网、导出外发或写入能力时，重新评估最小权限和操作审计。

### 7.4 配额、预算与公平性

同时限制用户、工作空间和供应商的请求速率、并发 Run、排队任务、存储、页数、Token 和费用。IP 限流仅作为辅助；设置闲置限流键过期，避免状态无界增长。

预算采用提交前估算/预留、执行中核算和结束后结算，使用原子更新避免并发超额；预估与真实账单差异单独记录。供应商未知用量显示未知，不能按零成本计入。

## 8. 隐私、删除与审计

默认不把论文原文、完整 Prompt、完整模型思考和用户会话发送到遥测系统。产品轨迹优先展示工具操作、证据、阶段摘要和停止原因；原始推理内容是否存储需单独确定保留策略。

区分用户笔记、私有会话、共享论文、评测样本和系统审计的保留期。审核者身份从登录态获取，安全审计记录 actor、workspace、动作、资源、结果和时间，避免写入密钥和原文。

删除采用有状态流程：立即撤销访问并标记删除，后台清理全文索引、文本/视觉向量、对象、缓存、缩略图与导出；失败可重试并对账。历史 Run 中可能包含原文副本，应明确采用删除、脱敏或受控保留，不能仅删除源 PDF。

备份中的删除通过保留期和恢复后删除清单执行。恢复流程必须重放已生效删除及撤权记录，防止恢复后重新暴露数据。数据保留要求与“历史可追溯”发生冲突时，由明确政策决定，不能无期限默认保留。

## 9. 质量评测与发布门禁

### 9.1 固定数据集

建立版本化固定集，覆盖事实、方法、跨论文比较、公式、表格、图、不可回答、多轮指代、低质量解析和提示注入。训练/调优样本与保留测试集分离，按论文划分以减少泄漏；Synthetic QA 保持候选状态。

沿用 `HUMAN_ACCEPTANCE.md` 的盲标、独立复核和 Judge 校准。多人模式中标注身份与权限由服务端校验。生成与 Judge 同模型可能共享偏差，应以独立 Judge、人工抽样和校准集交叉验证，而非简单增加打分次数。

### 9.2 指标与对照实验

| 层面 | 重点指标或检查 |
| --- | --- |
| 解析 | 页/块覆盖、阅读顺序、标题层级、表格和公式保真、bbox 定位 |
| 检索 | Recall@k、MRR、nDCG、跨论文覆盖、范围与租户隔离 |
| 证据 | 来源有效率、语义支持精度、矛盾与证据不足识别、引用完整性 |
| 回答 | 任务完成、数值条件正确、不可回答拒答、比较口径正确 |
| Agent | 工具范围、重复调用、停止原因、失败恢复、多次运行稳定性 |
| 运行 | 排队/首字/完整回答延迟、供应商失败、取消延迟、每次与每成功任务成本 |

至少对照单轮与 Agent、文本与图文、不同重排及模型版本。记录样本量、重复次数和不确定性，不能用少量均值或 Synthetic 分数直接声明质量提升。模型能力评测与不允许回归的既有能力分开管理。

### 9.3 CI 与测试层次

- 每次变更：Ruff、格式、单元与集成测试、Web 类型检查与构建、迁移校验。
- 浏览器冒烟：登录、上传、选论文、问答、引用跳转、断线恢复、取消、历史恢复、退出。
- 安全回归：双工作空间与双用户枚举所有对象访问入口；覆盖私有/共享会话和成员撤权。
- 故障注入：供应商 429/超时、Worker 退出、重复消息、取消完成竞争、对象或向量写入失败。
- 定期与发布前：固定质量集、并发与公平性压测、备份恢复、索引回滚及迁移演练。

真实供应商测试单独触发并限制预算，不作为每次普通提交的默认付费步骤。发布保存代码提交、数据集、Prompt、模型、索引和配置清单，支持复现与回滚。

## 10. 可观测性、部署与恢复

保留业务事件轨迹，增加结构化日志、指标和跨 API/Worker/Provider 的 trace_id 关联。可增加 OpenTelemetry 导出适配层；具体 GenAI 语义规范使用时核实版本与稳定性，避免事件存储依赖持续变化的遥测格式。

优先监控：队列深度与最老任务年龄、租约失效、各阶段 P50/P95、首字与完整回答时间、Provider 429/错误/熔断、取消耗时、成本、删除积压、索引不一致、权限拒绝和存储容量。租户与 Run 的高基数字段放入受控日志/Trace，避免无界指标标签。

部署补充非 root 用户、最小运行镜像、健康与就绪探针、优雅退出、依赖扫描和锁文件构建。Liveness 不因短暂供应商故障重启服务；Readiness 与供应商降级状态区分，避免外部故障触发整个服务反复摘除。

正式设定 SLO 前，先按论文规模、页数、问题类型、并发与供应商限额建立基线。延迟必须分解排队、检索、生成和验证，不用健康检查成功率代替业务可用性。

备份覆盖数据库、对象、向量索引或其可重建依据、配置版本和密钥恢复流程。远程 Qdrant 使用匹配部署方式的快照或重建机制，不能假设本地数据目录备份包含远程向量。设定 RPO/RTO，定期恢复到隔离环境并验证权限、引用、索引和删除状态。

## 11. 分阶段实施与验收

以下按依赖排序，不承诺日历工期。每阶段先拆成独立可验收任务，并记录迁移、费用和兼容性影响。

### 阶段 A：可信基线与多用户契约（P0）

交付：修正支持状态含义、建立固定评测基线；定义 Workspace、身份、资源可见性与权限矩阵；工具范围强约束；上传上限；共享 Provider 并发和 Run 预算；建立 CI。

验收：无证据支持的引用不能显示验证成功；空范围不扩大；工具不可越出用户范围；Provider 总并发符合配置；身份与多用户迁移设计形成评审记录。

### 阶段 B：多用户基础设施与数据迁移（P0）

依赖 A 的资源归属和权限契约。

交付：PostgreSQL Schema 与迁移、OIDC/会话认证、Membership、授权服务、私有对象存储、租户向量过滤、带归属的事件与任务、前端认证及 SSE 闭环。

验收：端到端双租户和私有会话隔离、撤权与导出检查通过；旧数据归属明确、迁移清单与恢复演练通过。此阶段通过前不开放多人共享部署。

### 阶段 C：独立 Worker 与可靠执行（P1）

依赖 B 的共享任务、事件和存储。

交付：问答/摄取/评测 Worker、租约、检查点、幂等、取消、优先级、公平调度、Provider 跨实例配额、索引激活与对账。

验收：API 多副本、Worker 重启和重复投递不会导致重复激活或事件串扰；可复用已完成阶段；供应商不确定调用有记录；一个工作空间的批处理不耗尽其他空间的全部在线能力。

### 阶段 D：证据可信与科研工作流（P1）

依赖 A 的评测；会话与共享能力依赖 B。

交付：Claim 语义验证、结构化比较、上下文与证据记忆、渐进式视觉读取、局部纠错重建、笔记与导出。

验收：在保留测试集上证明目标能力提升，报告质量、延迟和成本变化；数字与实验条件可核验；错误父轮不自动成为后续事实；所有导出保持权限与证据来源。

### 阶段 E：发布运营与容量扩展（P1/P2）

交付：生产监控、SLO、配额告警、完整删除、备份恢复与回滚 Runbook、容量压测、模型/索引影子发布；随后按实测负载扩容。

验收：在事先声明的并发、语料规模与预算下达到设定 SLO；恢复满足约定 RPO/RTO；故障和权限回归通过。安全、恢复和质量关键门禁不能以扩容替代。
