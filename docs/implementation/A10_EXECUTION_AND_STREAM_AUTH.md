# A10：执行授权传播与 SSE 持续授权

日期：2026-10-25。状态：已实现并完成本地回归；真实供应商与浏览器端未端到端验收。

## 1. 授权上下文传播

authorization.py 提供 AuthorizationGuard 与 ContextVar 绑定，限定用户、空间和本次文档快照。并行检索和 asyncio 子任务继承本次上下文，不共享可变的全局租户。

执行边界：

1. 后台开始前重新验证用户会话、成员关系和 Run 归属。
2. RetrievalService 要求 session 模式存在 Guard；检索范围只能缩小，返回候选再次检查归属。
3. ToolRuntime 自动采用绑定的服务端上下文，维持 A02/A08 的范围和实时授权约束。
4. Provider 在请求、重试、等待并发槽后和非流式结果返回时检查授权；流式数据在每次有效 payload 输出前检查。
5. 最终回答写入前再次检查，拒绝超范围引用。用户或文档授权失效时不保存成功答案。

授权轮询任务负责取消长时间没有返回数据的模型请求。当前默认间隔 1 秒；取消只能停止本地等待和后续步骤，已经送往供应商的请求可能继续产生费用，不承诺撤销已发送的数据。

## 2. SSE

连接开始前验证私有 Run，重连时再次认证；Last-Event-ID 只控制重放位置，不能改变授权。负数或非法游标返回 422。

每个事件发送前重新检查会话、成员、Run 和文档范围。空闲时在配置轮询间隔醒来检查。失权后仅发送不含业务内容的 `access.revoked` 控制事件并结束连接，不再发送排队中的私有事件。

HTTP 已开始后不能改成 401/403，因此使用静态控制事件；新连接仍按正常认证状态拒绝。已发送的字节无法收回；检查与网络发送之间并非跨系统原子操作，不能将轮询描述为绝对即时撤权。

受保护响应仍使用 private,no-store；SSE 禁止反向代理缓冲。Bearer Header 需要 Fetch 流式客户端，现有浏览器原生 EventSource 登录闭环仍待改造。

## 3. Langfuse

工作空间问答从已验证的持久化归属传播真实 user_id 和 workspace_id，Conversation 继续映射为 Session。它们用于观测分组，不作为业务授权或 Langfuse 项目内访问隔离。

默认正文导出仍关闭。单个 Langfuse 项目可包含多用户 Trace，不应将控制台直接开放给普通 ScholarRAG 用户。停止业务输出不删除之前已导出的遥测；数据保留与删除策略需独立实现。

## 4. 验证

本轮结果：完整后端 175 项通过，Ruff 与格式检查通过。新增真实 SDK 内存 exporter 用例确认 user_id 与 workspace_id 传播到子 Observation；Provider 排队后重新授权也有独立回归。

tests/test_workspace_queries.py 覆盖：两个并发用户的 Guard 隔离、无 Guard 的 session 检索拒绝、范围扩张拒绝、撤权后丢弃回答、空闲执行任务取消、SSE 每事件撤权和断线游标重放。既有工具与 Langfuse 内存 exporter 回归继续执行，无真实模型费用。

后续需要基于真实供应商、反向代理和浏览器 Fetch 流做端到端验收，压测轮询与数据库开销；多实例前替换进程内任务/条件变量，并补充授权变更版本、共享通知及可审计的任务身份策略。
