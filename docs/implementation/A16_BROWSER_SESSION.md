# A16：浏览器会话与工作空间入口

实施日期：2026-10-26。状态：会话令牌登录、退出和工作空间切换已接通；OIDC / 自助注册仍未实现。

## 本次交付

新增 `/workspace` 页面，旧首页提供“进入工作空间”链接。该页面使用现有服务端签发的可撤销会话令牌登录，读取 `/api/me` 与 `/api/workspaces` 后显示用户和已加入的工作空间。页面不创建用户、不自行分配角色，也不把某个客户端 ID 当作真实身份。

登录成功后可选择工作空间，显示当前角色并进入论文和上传页面。未加入任何空间时显示明确空状态；“刷新工作空间”重新读取成员资格和角色，即使空间 ID 相同，也会重新建立页面作用域。

这是将现有会话认证接入浏览器，不是 OIDC、账号密码登录或完整身份平台。可信管理员仍通过 `scholarrag auth create-user / create-workspace / issue-session` 预置身份与会话，令牌有效期沿用后端配置。

## 凭据与生命周期

API 客户端位于 `web/lib/workspace-api.ts`，使用私有字段保存令牌。应用仅在当前页面内存中持有它，不写 localStorage、sessionStorage、Cookie、查询参数或日志，也不将令牌嵌入 PDF 下载链接。静态预渲染的登录页不包含私人数据。

- 输入为密码字段，提交后立即清空；应用请求浏览器关闭自动填充，但浏览器自身的密码管理行为仍由用户控制。
- 每次请求显式发送 Authorization；关闭 HTTP 缓存与 Cookie 发送，禁止跟随重定向，避免将认证流程隐式转给其他地址。
- 登录、刷新工作空间请求有 AbortController 和操作序号，过期响应不会覆盖新会话。
- 切换工作空间会卸载旧内容作用域，取消请求、停止轮询并释放 PDF 对象 URL；不会将前一个空间的论文、任务和选定文件复用到新空间。
- 点击退出先清空本地身份和私人内容，再调用 DELETE `/api/me/session` 撤销服务端会话。服务器已返回 401 时同样视为会话无效；网络失败时明确提示服务端注销尚未确认，不能谎报已撤销。
- 401 回到登录页；403 清除当前工作空间内容并要求刷新权限。已下载到磁盘的文件不受页面清理影响，无法通过本地退出“收回”。

刷新页面后需要重新输入令牌；这已在浏览器验证。应用内存策略不能消除 XSS、恶意浏览器扩展或主机运维访问的风险。后续接入 OIDC 与服务端会话时，需要单独设计回调、Cookie、CSRF、退出和多标签行为，本批不伪造这些能力。

## 部署配置

API 需启用 session 模式，前端需配置正确的 API 地址：

```dotenv
SCHOLARRAG_AUTH_MODE=session
NEXT_PUBLIC_API_BASE=http://localhost:8000
SCHOLARRAG_API_CORS_ORIGINS=["http://localhost:3000","http://127.0.0.1:3000"]
```

`NEXT_PUBLIC_API_BASE` 是构建时公开配置，修改后重建 Web。`api_cors_origins` 新增为 API Settings 的 JSON 数组，默认保持原有两个本地 Origin；部署时配置完整、准确的 Web Origin。API 的 Bearer 认证仍是实际权限边界，CORS 配置不代替认证。

CORS 允许浏览器预检携带 Authorization 和 Idempotency-Key；允许的 Origin 也能读取 401 响应，从而显示重新登录提示。没有新增任何公开创建身份或签发会话的接口。

## 验收

新增后端浏览器集成 4 项回归：允许和拒绝的 Origin、认证错误响应可读取、退出后服务端 token 失效，以及默认测试应用的数据目录隔离。前端客户端共 19 项测试覆盖传输约束、错误脱敏、授权 PDF、取消传播、响应体读取期间取消，以及原生 fetch 调用接收者。

浏览器以 `tests/browser_fixture.py` 的一次性目录、合成用户和 PDF 进行交互验收，已验证：错误令牌提示、有效令牌登录、角色显示、两个工作空间切换、刷新页面不保留登录、退出清空内容、注销后的旧 token 不能再次登录。未使用真实身份、论文或供应商服务。

本批结果：后端 **221 项通过**；前端 **19 项通过**；Ruff、格式检查、TypeScript 与 Next.js 生产构建通过。前端测试已加入 CI，但尚未推送触发远端 CI。

## 测试隔离修正与上一批记录更正

本批发现：此前 `tests/conftest.py` 已隔离私有 `.env` 与供应商网络，但没有隔离测试收集时模块级默认应用的数据目录，导入 `api.main` 会初始化项目默认 `data/scholarrag.db`。只读检查确认默认库已经采用 v4 工作空间队列结构。因此 A14 和先前聊天中的“实际目录尚未迁移”不能继续作为事实依据。

现在从 `pytest_configure`、即收集导入前开始，将 `SCHOLARRAG_DATA_DIR` 指向临时目录，结束时清理，并新增回归断言模块级默认应用确实使用该目录。原有显式 `tmp_path` 测试仍保持隔离。

旧任务删除符合用户此前明确要求，迁移 SQL 不删除 PDF、解析文件或文献记录；这里更正的是执行时点和验证环境的描述。默认库当前已是新结构，不能再承诺旧任务仅会在“下一次启动”才被清理。
