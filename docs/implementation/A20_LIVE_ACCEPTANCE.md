# A20：完整浏览器主流程的真实供应商验收

验收日期：2026-10-26。结果：本轮指定的工作空间浏览器主流程通过小规模真实联调。它不是整体生产上线验收，也不代表论文质量 Gold 或性能基准通过。

## 环境和调用范围

用户已明确允许真实测试。使用项目已配置的 MinerU 与 SiliconFlow，创建一次性工作空间、两个测试用户和自行编写的两页 PDF；未上传用户论文、个人资料或第三方非公开内容。

所有业务数据、源文件、SQLite 和嵌入式 Qdrant 都位于专用临时目录。未使用项目默认数据目录或生产向量库。没有将供应商密钥、签名链接、原始 provider response 或认证头写入仓库验收附件。

启动工具是 `tests/live_browser_fixture.py`，显式运行才会创建环境，不进入 pytest。它不会自动提交付费上传/问答；实际提交由浏览器操作完成。临时目录带标记，可以通过 `--resume` 恢复同一测试数据；拒绝恢复未标记的目录。

测试配置：关闭解析回退、自动 Provider 重试和模型思考；使用默认配置的聊天模型与 embedding/rerank，限制为一次两页上传与两轮直接检索问答。重启恢复已完成 Run、刷新历史、SSE 重连和集合选择不重新发起模型问答。

Langfuse 当前未配置项目密钥，真实测试没有开启导出，不能把本次本地事件与流式验收写成 Langfuse Cloud 导出成功。

## 自动回归与复现

本批后端增加 2 项首页模式测试，完整 **223 项通过**。前端增加 12 项（含 7 项 SSE），完整 **31 项通过**。Ruff、全量格式、TypeScript 与 Next.js 生产构建通过；远端 CI 尚未推送触发。

cd web
npm run lint

在仓库根目录显式启动真实测试环境，会读取已配置的真实供应商凭据：

```bash
.venv/bin/python tests/live_browser_fixture.py
```

另一个终端启动 Web，登录脚本打印的**一次性测试会话**，选择 Live Acceptance，上传打印路径中的 authored PDF，再手动提交问题。端口 8000/3000 需空闲。普通不调用供应商的浏览器 Fixture 仍为 `tests/browser_fixture.py`。

恢复已完成测试数据不重新建身份或上传：

```bash
.venv/bin/python tests/live_browser_fixture.py --resume /tmp/scholarrag-live-browser-REPLACE
```

实际目录名称以脚本输出为准；本次验收完成后停止测试进程，临时目录可用于本地复核，仓库仅持久化上述脱敏附件。

## 限制和下一阶段

- 本次不是长时稳定性、并发容量、生产反向代理或多实例恢复测试。验证的是已配置的云端 v4 协议，不能据此推断 MinerU 产品或服务端引擎的 4.x 版本。
- 真实付费链路仅覆盖文本 PDF 与直接检索问答。工具 Agent、多步规划和停止 API 已接通并由已有后端/新增客户端离线回归覆盖，未额外付费执行这两个模式；视觉证据没有测试。
- 解析后的标题被抽取为首个章节 `1. Method`，而非封面标题。正文、数值与页级引用可用，但文档标题识别仍需完善。
- 引用定位正确不等于语义支持自动验证完成；本次已人工核对这两个问题，不替代独立真人 Gold 和语义验证器。
- OIDC、独立 Worker、租约/检查点、费用预算、PostgreSQL/对象存储和恢复演练仍未完成。
- 评测与解析审核的多人 API/UI 尚未迁移，不能将本轮“浏览器主流程完成”解读为整个实施计划完成。
